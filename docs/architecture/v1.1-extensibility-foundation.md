# PMCS V1.1 — Extensibility Foundation Contract

- Stage: `V1.1-EXT1`
- Contract schema: `pmcs.module/v1`
- Platform contract version: `1.1.0`
- Runtime baseline: PMCS V1 remains locked; implementation is isolated on `v1.1-development`
- Status: Implementation candidate

## Purpose

قابلیت‌های آینده PMCS ــ از PMO و PMBOK تا متره، برآورد، MSP و Agentهای تخصصی ــ باید از قراردادهای کنترل‌شده وارد محصول شوند، نه با دسترسی مستقیم به Persistence، تغییر موردی Navigation یا دورزدن Permission Engine.

EXT1 یک Marketplace یا Plugin Loader نیست. Runtime هیچ Binary، Assembly، HTML، CSS یا JavaScript دلخواه را بارگذاری نمی‌کند.

## Module contract

هر ماژول جدید باید یک `ModuleDescriptor` با این مرزها منتشر کند:

- `moduleId` و Semantic Version؛
- Capability و dependency صریح؛
- `migrationOwner` یکتا و `minimumPlatformVersion`؛
- Permission، Navigation، Agent Tool و Integration Event manifest؛
- Schema version شناخته‌شده.

Schema ناشناخته، dependency مفقود یا چرخه‌ای، شناسه تکراری، Permission اعلام‌نشده، Route ناامن، JSON schema نامعتبر و Platform version ناسازگار باعث توقف Startup می‌شود. این رفتار عمداً Fail-Closed است.

ماژول‌های V1 تا مهاجرت تدریجی با Schema صریح `pmcs.module/legacy-v1` ثبت می‌شوند. Legacy descriptor هیچ Capability، Navigation، Permission، Event یا Tool منتشر نمی‌کند و بنابراین به‌صورت ضمنی قابل توسعه یا فراخوانی نیست.

## Central authorization

Manifest فقط Permission مورد نیاز را اعلام می‌کند؛ تصمیم نهایی همیشه با `IProjectPermissionService` است. Endpoint کاتالوگ به `platform.modules.read` نیاز دارد. `platform.modules.manage` فقط برای Tenant Administrator قابل دسترسی است و در این Slice هیچ Mutation یا Activation endpoint وجود ندارد.

## Navigation contract

Navigation شامل Route داخلی، Label، Permission، Feature Flag و Order است. Client فقط Schema جاری، Route داخلی امن، Permission اعطاشده و Feature فعال را نمایش می‌دهد. Contract ناشناخته یا ناقص به‌جای نمایش خوش‌بینانه حذف می‌شود.

## Agent tool contract

هر Tool باید Input/Output JSON schema، Permission، Risk Class و Access Mode داشته باشد. Reference Tool یعنی `platform.modules.describe` فقط Read-only است. این Stage اجرای عمومی Tool یا دسترسی Agent به Database را فعال نمی‌کند.

مرز Agent بدون تغییر می‌ماند:

`Agent → Permission-aware Tool → Application Service → Business Rules → Database`

## Versioned events and application contract

`IntegrationEventManifest` نام، نسخه مثبت و Classification را ثبت می‌کند. Reference event یعنی `platform.module-catalog.snapshot:v1` از طریق همان descriptor کشف می‌شود. انتشار Business Event همچنان فقط از Outbox موجود مجاز است؛ Manifest مجوز bypass آن نیست.

`IModuleCatalog` تنها Application Contract مشترک این Slice است. ماژول‌ها حق خواندن DbContext یا Persistence یکدیگر را ندارند و Architecture Gate موجود این مرز را کنترل می‌کند.

## Reference path

Reference Module یعنی `platform.foundation` این زنجیره را اثبات می‌کند:

1. Descriptor در Startup اعتبارسنجی و ثبت می‌شود؛
2. Endpoint permission-aware آن را ارائه می‌کند؛
3. Client قرارداد Navigation را با Permission و Feature Flag resolve می‌کند؛
4. Permission، Event و Tool metadata با Contract test بررسی می‌شوند؛
5. Unknown schema و Route/Dependency/Permission نامعتبر Fail-Closed می‌شوند.

## Deferred work

- Remote/Dynamic plugin loading؛
- Asset pipeline مشترک در `V1.1-DOC1`؛

موشن، تصویر و تم Login در IAM1 به‌صورت `LoginExperienceDescriptor` نسخه‌دار و دارای Preview، Publish، Rollback و Fallback پیاده می‌شوند؛ این تنظیمات از Authentication جدا می‌مانند.
