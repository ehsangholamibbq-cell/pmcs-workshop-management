# ADR 0032 — انتخاب کنترل‌شدهٔ ارائه‌دهنده و مدل در INT1

- وضعیت: Accepted / تصمیم مالک محصول
- تاریخ: ۱۴۰۵/۰۷/۰۹ (۲۰۲۶-۱۰-۰۱)
- Change record: `V1.1-INT1-MODEL-SELECTION`
- Parent: `PMCS-RM-AGENT-001` و `PMCS-RM-POST-V1-001`
- دامنه: طراحی و معیار پذیرش `V1.1-INT1` / `AGENT-S1`؛ اجرای Runtime هنوز آغاز نشده است.

## زمینه

مالک محصول می‌خواهد بتواند موتور مدل Agent مدیریتی را میان GPT/OpenAI، Gemini/Google،
Claude/Anthropic و ارائه‌دهنده‌های آینده انتخاب کند. انتخاب فقط در سطح مدیریتیِ مجاز باشد.
مرز ابزار، مجوز و حقیقت رسمی PMCS با تغییر مدل تغییر نمی‌کند. V1 دارای Advisory محدود
با اتصال OpenAI است (`ADR 0011` و `docs/api/advisory-intelligence-v1.md`)؛ آن قرارداد تاریخی
V1 بازنویسی نمی‌شود و وجودش اثبات چندارائه‌دهنده‌ای بودن INT1 نیست.

## تصمیم

1. `PMCS.Intelligence` یک Model Gateway با آداپتور مجزا برای OpenAI، Google Gemini و
   Anthropic Claude دارد. فهرست مدل‌ها نسخه‌دار و قابل توسعه با آداپتور بعدی، از جمله
   مدل محلی، است؛ نام، endpoint و کلید در منطق کسب‌وکار ثابت نمی‌شوند. در INT1 هر سه
   خانوادهٔ نام‌برده باید مسیر اتصال و انتخاب قابل آزمون داشته باشند. مدل فاقد پیکربندی
   یا اعتبارسنجی فعال، قابل انتخاب یا اجرا نیست.
2. «پروفایل اجرا» نسخه‌دار، مورد استفاده، مدل پیش‌فرض، مدل‌های مجاز، قابلیت‌های لازم
   (از جمله tool calling و structured output)، محدودهٔ Tenant/Project، طبقه‌بندی دادهٔ
   مجاز برای ارسال، سقف مصرف/زمان و سیاست خطا را مشخص می‌کند. تغییر مدل، Profile را
   از نظر Permission یا ابزارهای در دسترس گسترش نمی‌دهد. در هر Request/Run شناسه و
   نسخهٔ Profile/Provider/Model/Prompt/Policy ثابت و ثبت می‌شود.
3. ثبت/فعال‌سازی Provider، Credential، Model و سیاست سراسری فقط با Permission مستقل
   مدیر ارشد سامانه انجام می‌شود. مدیر سازمان صرفاً در صورت تفویض صریح می‌تواند از
   allowlist همان Tenant برای پروفایل مجاز انتخاب کند؛ هیچ اختیار ضمنی از نقش عمومی
   «admin» استنتاج نمی‌شود. کاربر عادی مدل را عوض نمی‌کند. یک سطح مدیریت محدود و
   مجوزدار برای مشاهدهٔ قابلیت‌ها، وضعیت، انتخاب، انتشار نسخه و بازگشت لازم است؛
   Executive Intelligence UI و Chat عمومی جزو INT1 نیستند.
   قرارداد Permission در DoR با شناسه‌های مستقل مدیریت Provider و انتخاب Profile،
   دامنهٔ سراسری/Tenant و ممنوعیت تفویض ضمنی نسخه‌دار می‌شود.
4. PMCS فقط فراخوانی ابزارهای ثبت‌شدهٔ خود را از مسیر Permission-aware Tool Registry
   اجرا می‌کند و مجوز کاربر جاری را در هر فراخوانی دوباره می‌سنجد. آداپتور، تصمیم
   مدل دربارهٔ ابزار و خروجی ساختاریافته را به قرارداد داخلی تبدیل و schema را
   اعتبارسنجی می‌کند؛ ابزارهای داخلی/میزبانی‌شدهٔ Provider نباید مسیر دسترسی مستقیم
   به داده یا اجرای عمل در PMCS بسازند. دادهٔ ارسالی طبق Profile و Permission کمینه
   می‌شود؛ Secret و payload حساس در log/telemetry ثبت نمی‌شوند.
5. جابه‌جایی خودکار فقط به مدل از پیش تأییدشدهٔ همان Profile با قابلیت‌های لازم،
   طبقه‌بندی داده و سقف مجاز انجام می‌شود؛ در غیر این صورت Run با خطای صریح و امن
   پایان می‌یابد. خطا، timeout، پاسخ ناقص و schema نامعتبر حق افزایش دسترسی یا
   پاسخ ساختگی ندارند. غیرفعال‌سازی Provider/Model و rollback نسخهٔ Profile ممکن است.

## معیار پذیرش INT1

- سه آداپتور نام‌برده با contract/compatibility suite مشترک و آزمون اتصال واقعیِ
  پیکربندی‌شده قابل ارزیابی باشند؛ در نبود Credential نتیجه `Unavailable` صریح است،
  نه موفقیت صوری. تعویض مدلِ مجاز هیچ تغییری در Business Logic یا Tool Permission ندهد.
- تنها actor دارای Permission مدیریت بتواند کاتالوگ، Profile یا انتخاب مدل را تغییر
  دهد؛ تفویض Tenant محدود باشد و آزمون‌های منفی کاربر عادی، cross-tenant/project،
  privilege escalation و ابزار غیرمجاز پاس شوند.
- Run lineage مدل و نسخه‌های Profile/Prompt/Policy، تصمیم و دلیل fallback، مصرف و
  خطا را بدون Secret یا payload حساس ثبت کند.
- خطای Provider، خروجی نامعتبر، مدل فاقد قابلیت، عبور از سقف و fallback غیرمجاز
  fail-closed باشند؛ غیرفعال‌سازی و rollback در آزمون مستقل اثبات شوند.

## مرز مرحله

این مصوبه Foundation و سطح مدیریت محدود INT1 را تعریف می‌کند. Agent خواندنی کامل،
RAG، رابط عملیاتی Executive Intelligence، اقدام پیشنهادی/نوشتنی و Chat عمومی تنها
در Stageهای بعدی و Gate مستقل خود فعال می‌شوند.
