# ADR 0009 — Persian User Interface Boundary

- Status: Accepted
- Date: 2026-09-10

## Context

کاربران عملیاتی و مدیریتی محصول فارسی‌زبان‌اند و نباید برای ثبت واقعیت پروژه یا تصمیم‌گیری با واژه‌های فنی انگلیسی، نام enumها یا پیام خام Backend مواجه شوند. با این حال ترجمه نام‌های داخلی Domain، قرارداد API و schema پایگاه داده، پایداری Integrationها را کاهش می‌دهد و افزودن زبان‌های بعدی را دشوار می‌کند.

## Decision

- زبان و جهت پیش‌فرض رابط V1 فارسی و RTL است؛ عنوان مرورگر، Manifest، متن قابل مشاهده، راهنمای فیلدها، وضعیت‌ها و پیام‌ها باید فارسی باشند.
- نام‌های Domain، enumها، commandها، endpointها، error codeها و schemaهای API/Database انگلیسی و پایدار می‌مانند.
- مرز Presentation مسئول ترجمه مقادیر فنی به عبارت فارسی است. مقدار خام Backend یا کد خطا نباید مستقیماً به کاربر نمایش داده شود.
- پاسخ‌های خطای ساختاریافته در `lib/localization.ts` براساس error code و HTTP status به پیام امن فارسی تبدیل می‌شوند. شرح فارسی معتبر Backend قابل حفظ است، اما شرح انگلیسی به UI عبور نمی‌کند.
- مبلغ‌ها با رقم فارسی و نام فارسی ارز نمایش داده می‌شوند؛ currency code فقط در قرارداد داخلی باقی می‌ماند.
- مخفف‌های تخصصی ضروری مانند WBS، RFI و HSE فقط همراه معادل فارسی نمایش داده می‌شوند.
- گیت `npm run audit:fa` متن لاتینِ قابل مشاهده و عبارت‌های ترکیبی بدون معادل مجاز را در CI رد می‌کند.
- ساختار ترجمه در لایه مستقل نگهداری می‌شود تا افزودن locale انگلیسی در آینده بدون تغییر Domain و API ممکن باشد؛ انتخاب زبان کاربر خارج از این Checkpoint است.

## Consequences

- کاربران فارسی‌زبان با رابط، وضعیت و خطای یکدست روبه‌رو می‌شوند، حتی اگر پاسخ فنی سرور انگلیسی باشد.
- تیم توسعه می‌تواند زبان داخلی و قراردادهای Integration را بدون آمیختگی با متن نمایشی پایدار نگه دارد.
- داده‌های واردشده توسط کاربر، نام اشخاص، کد پروژه، شماره سند و فایل به‌عنوان داده اصلی ترجمه نمی‌شوند.
- هر قابلیت UI جدید باید نگاشت وضعیت و خطای خود را پیش از عبور از گیت فارسی کامل کند.
