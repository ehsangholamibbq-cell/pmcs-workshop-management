# ADR 0034 — پذیرش کامل مالک محصول و ترتیب انتشار V1.1

- وضعیت: Accepted / تصمیم مالک محصول، ۲۰۲۶-۱۰-۰۱
- Change record: `V1.1-OWNER-ACCEPTANCE-AND-RELEASE-GATE`
- Parent: ADR 0033 و `PMCS-QA-V1.1-001`
- اثر: ترتیب اجباری پایان V1.1، پذیرش دستی مالک، انتشار و شروع نسخه‌های بعدی.

## زمینه

پس از تکمیل توسعهٔ V1.1، مالک محصول خودش باید کل نسخه را روی نامزد انتشار
بررسی و آزمایش کند. QA1 و قفل Baseline شواهد فنی و ماشینی‌اند و جای آزمون و
پذیرش واقعی مالک محصول را نمی‌گیرند. انتشار عمومی/عملیاتی پیش از ثبت پذیرش مالک
مجاز نیست.

## تصمیم

ترتیب اجباری چنین است:

1. اجرای QA1 کامل طبق Test and Qualification Contract روی Candidate ثابت؛
2. ثبت وضعیت‌های `Qualified → Final → Baseline Locked` با Commit، Artifact، Hash
   و گزارش‌های هم‌نسخه؛
3. آماده‌سازی Candidate قابل بررسی و ثبت آن در [چک‌لیست پذیرش مالک V1.1](../release/pmcs-v1.1-owner-acceptance.md)؛ این Candidate پیش از پذیرش، انتشار عمومی/عملیاتی محسوب نمی‌شود؛
4. اجرای آزمون کامل دستی مالک محصول و ثبت نتیجه، محیط/نسخهٔ آزمون‌شده، موارد قبول/رد،
   نقص‌های باقیمانده و تصمیم صریح `Accepted`؛
5. در صورت شکست مورد مسدودکننده، انتشار متوقف می‌ماند؛ اصلاح Runtime Candidate جدید
   می‌سازد و QA و پذیرش متأثر باید دوباره اجرا شوند؛
6. انتشار/استقرار رسمی V1.1 فقط پس از پذیرش ثبت‌شدهٔ مالک مجاز است؛
7. آغاز هر کار نسخهٔ بعدی، از جمله V1.2 و `AGENT-S1-LIVE`، فقط پس از تأیید انجام انتشار
   V1.1 مجاز است. در V1.2، `AGENT-S1-LIVE` پیش‌نیاز Agent Stage 2 باقی می‌ماند.

آزمون دستی مالک باید روی همان Candidate/نسخه‌ای انجام شود که Hash آن در فرم پذیرش
ثبت می‌شود. اگر پس از آزمون Runtime عوض شود، پذیرش آن Candidate به نسخهٔ تازه منتقل
نمی‌شود. انتخاب محیط اجرای آزمون با مالک محصول است؛ هیچ API key یا اتصال واقعی Provider
برای بستن این دروازهٔ V1.1 لازم نیست، چون INT1 در V1.1 خاموش تحویل می‌شود طبق ADR 0033.

## تفکیک Gateها

`QA1` = Qualification خودکار/مهندسی؛ `Baseline Locked` = قفل فنی/نسخه‌ای؛
`OWNER-ACCEPTANCE` = آزمون کامل دستی و قبولی صریح مالک؛ `PUBLISHED` = انتشار رسمی.
این Gateها مستقل‌اند و هرکدام Evidence جدا دارند. تا ثبت `PUBLISHED`، V1.2 و مراحل Agent
بعدی Planned/Held باقی می‌مانند.

## شواهد مورد انتظار

- شناسه و SHA کامل Candidate؛
- محیط و زمان آزمون دستی؛
- نتیجه برای هر بخش چک‌لیست و لینک/مرجع شواهد یا Issueهای نقص؛
- نقص‌های باز با شدت و تعیین تکلیف؛
- تصمیم صریح مالک (`Accepted` یا `Rejected`)، تاریخ و توضیح؛
- مرجع انتشار رسمی V1.1 و تاریخ آن؛
- تنها پس از انتشار: مجوز شروع برنامهٔ بعدی.
