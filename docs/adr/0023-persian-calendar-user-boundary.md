# ADR 0023 — Persian calendar at every user boundary

- Status: Accepted
- Date: 2026-09-12

## Decision

تمام تاریخ‌های قابل مشاهده یا قابل ورود در رابط فارسی PMCS با تقویم هجری شمسی، ارقام فارسی و منطقه زمانی پروژه (`Asia/Tehran` در V1) ارائه می‌شوند. این قاعده شامل فرم، فیلتر، جدول، داشبورد، اعلان، تاریخچه و خروجی‌های قابل ارائه به کاربر است.

مرز ذخیره‌سازی و تبادل تغییر نمی‌کند:

- تاریخ بدون ساعت در API با `YYYY-MM-DD` و در Backend با `DateOnly` نگهداری می‌شود؛
- لحظه زمانی در API با ISO 8601 UTC و در Backend با `DateTimeOffset` نگهداری می‌شود؛
- PostgreSQL از `date` و `timestamptz` استفاده می‌کند؛
- تبدیل شمسی فقط در مرز User Interface انجام می‌شود.

## Enforcement

- `PersianDateInput` تنها ورودی مجاز تاریخ در رابط است؛
- `lib/persian-date.ts` تنها مرجع تبدیل، قالب‌بندی و تاریخ مدنی تهران است؛
- Locale صریح `fa-IR-u-ca-persian-nu-arabext` استفاده می‌شود؛
- `audit:calendar` ورود دوباره `date/datetime-local/month/week` بومی مرورگر و قالب‌بندی مستقیم تاریخ در UI را رد می‌کند؛
- تبدیل نوروز، اسفند کبیسه، ارقام فارسی/عربی/لاتین، مرز UTC تهران و چیدمان شنبه‌اول تست می‌شوند.
- بخش تاریخِ شماره‌های رسمی جدید از تقویم شمسی و روز مدنی تهران ساخته می‌شود؛ شماره‌های تاریخی هرگز بازشماری نمی‌شوند.

## Consequences

مرتب‌سازی، قیود پایگاه داده، همگام‌سازی آفلاین و Integrationها روی قالب استاندارد باقی می‌مانند؛ در عین حال کاربر هیچ تاریخ میلادی یا ISO خامی در UI نمی‌بیند. کد تاریخ در شناسه‌های رسمی با رقم لاتین باقی می‌ماند تا interoperability، جست‌وجو و Barcode آسیب نبیند، اما مقدار آن شمسی است. هر خروجی PDF/Excel یا ماژول جدید باید پیش از انتشار از همین مرز مشترک استفاده کند و در غیر این صورت Release Gate شکست می‌خورد.
