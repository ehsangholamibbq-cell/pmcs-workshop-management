## مرز پذیرفته‌شده

سه Adapter، Catalog و Profile نسخه‌دار، Grant مستقل و تفویض محدود، rollback،
Tool Registry چهار قرارداد خواندنی مالک، Run تک‌نوبتی، fallback با سقف، cancellation،
recovery، Audit/Outbox/receipt فقط metadata و migration/restore با fixture متصل و
آزمون‌های منفی tenant/project/permission بررسی شده‌اند. تعویض مدل در fixture همان
Business Logic و Tool Permission را حفظ می‌کند. Run 674 شواهد Source را می‌دهد؛
Run 676 تصمیم release را با همین کد و نسخه‌های اسناد ارزیابی می‌کند.

در Source، Reference Run فقط وقتی `Intelligence:INT1ReferenceEnabled=true` باشد
فعال می‌شود و Recovery Worker در حالت false بلافاصله خارج می‌شود. این تنظیم در
`appsettings.json` فعال نیست؛ migrationها Grant یا Provider/Model را Seed نمی‌کنند.
آزمون Governance همین مرز را کنترل می‌کند. این شواهد پیکربندی یک استقرار آینده را
به‌جای QA1 تأیید نمی‌کنند.

## Gateهای باز

- QA1 باید در Candidate انتشار خاموش‌بودن INT1، نبود Grant راه‌انداز، Provider/Model
  فعال در Registry INT1 و Credential ویژهٔ INT1، default-deny مدیریت، Regression
  Advisory تاریخی V1، Migration/Restore و Full Regression را اثبات کند.
- `R-AI-03` و آزمون اتصال واقعی OpenAI/GPT، Google/Gemini و Anthropic/Claude با
  structured output و tool calling تا `AGENT-S1-LIVE`، نخستین Gate Intelligence
  پس از قفل V1.1، باز هستند. `Unavailable/allAvailable=false` قبولی نیست.
- `AGENT-S1` هنوز Qualified نهایی نیست؛ Stage 2 و فعال‌سازی INT1 در Pilot/Production
  ممنوع‌اند. QA1 و قفل Baseline V1.1 در زمان ثبت این Checkpoint آغاز نشده‌اند.

این Checkpoint تنها مجوز ورود به QA1 برای نسخهٔ فاقد Runtime فعال Agent است؛
هیچ گواهی برای استفادهٔ عملیاتی Agent صادر نمی‌کند.
