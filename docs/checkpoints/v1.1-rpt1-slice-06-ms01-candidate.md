## مرز این Micro-Step

این Checkpoint نخستین مرز امن پس از فعال‌شدن روش Micro-Step است. هیچ معماری، API خارجی،
Migration، Scope یا ترتیب Roadmap تغییر نکرده است. هدف فقط Implement و Verify کردن Core لازم برای
Qualification ظرفیت در Micro-Step بعدی است:

1. بودجه‌های fail-closed و bounded برای attempt، retry delay، PDF facts، XLSX rows، output bytes،
   processing timeout و queue-age warning؛
2. timeout مستقل هر claim با diagnostic برابر `reporting.run.timeout`؛
3. تبدیل Run که attempt نهایی آن پس از crash کهنه شده است به شکست نهایی
   `reporting.retry.exhausted` همراه Audit، به‌جای ماندن دائمی در `Processing`؛
4. claim عادلانه‌تر میان پروژه‌ها با position داخل صف پروژه، آخرین زمان خدمت پروژه و
   `FOR UPDATE OF candidate SKIP LOCKED`؛
5. اعمال budgetهای PDF/XLSX و حداکثر byte در همان Application/Renderer boundary؛
6. Meterهای کم‌کاردینالیتی برای claim/outcome/duration/output size/queue age/heartbeat؛
7. health check آماده‌به‌کار برای heartbeat و oldest queue age، با وضعیت `Degraded` به‌جای Healthy
   کاذب؛
8. failure injection هدف‌دار `BeforeStorageTransientFailure` فقط پشت
   `PMCS_QA_GATEWAY_ENABLED=true` برای Qualification poison-run؛
9. Harness مقدماتی ۲۰ Run سالم و یک poison Run برای Micro-Step بعدی.

`20 healthy + 1 poison` و fairness جدید را هنوز در orchestration اختصاصی اجرا نکرده است. بنابراین:

  تولیدی هنوز Gate عملیاتی مستقل‌اند؛
